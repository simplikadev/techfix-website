# TechFix setup
1. Create a Supabase project (choose EU region). Run supabase/schema.sql once in SQL Editor on a new project.
2. Authentication > Users: create your own admin user with a strong password. Disable public signups. Copy its UUID and run `insert into public.admins(user_id) values ('YOUR-UUID');` in SQL Editor. Never grant admin to customers.
3. Edit config.js with project URL and public anon/publishable key only. Never put service-role keys or Telegram tokens in the website.
4. Serve locally using `python -m http.server 8000` and open http://localhost:8000. Test booking, admin login, status updates, anonymous read denial and non-admin access denial.
5. Deploy static files to a host that permits commercial sites (e.g. Cloudflare Pages, subject to current terms). For a noncommercial portfolio, GitHub Pages: push index.html, app.js, config.js, style.css to repository root; Settings > Pages > Deploy from branch > main / root. GitHub Pages is not intended for commercial transaction-focused sites; use a suitable commercial host for live repair booking. Hash navigation works on either host.
6. Telegram: create a separate bot with BotFather, send it a message and obtain your chat ID using Telegram getUpdates privately. Install Supabase CLI, log in, link project, then run `supabase secrets set TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... WEBHOOK_SECRET=...` (use a long random secret). Run `supabase functions deploy notify --no-verify-jwt`. In Database Webhooks create an INSERT webhook on public.bookings to https://YOUR_PROJECT.supabase.co/functions/v1/notify with header x-webhook-secret set to the same secret. Test a booking. Notification contains no customer data. Check webhook/function logs if delivery fails; no automatic retries implemented.
7. Before launch: replace operator/contact/privacy placeholders, confirm service prices, legal registration and work authorization, add genuine portfolio projects. Complete GDPR notice, retention/deletion procedure, processor agreements and hosting disclosures. Public booking RPC has basic per-email throttling only; add CAPTCHA and IP-based rate limiting through a server-side endpoint and revoke public RPC access before public launch. Do not solicit passwords or sensitive information. Confirm appointments manually and contact customers by email yourself. No automatic customer email or calendar sync. Exact confirmed slot duplicates are blocked; overlapping appointments of different start times are not. No availability calendar; requests are preferences only. Admin interface is English. All public pages support DE/EN/UK. Free tiers subject to provider limits.
